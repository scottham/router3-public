# 已知限制与上线阻断项

[English](KNOWN_LIMITATIONS.md)

主要路径为 API Key 从钱包共享预付池扣费；高级路径为客户端自签 x402 通道凭证。

1. 计量仍需信任平台：链上无法证明 token 用量。x402 原生方式把平台能扣的钱限定在用户每次签的上限内；API Key 方式在钱包共享池记账，合约限制钱包每日扣款、补充与固定 Treasury，Key 硬额度由网关执行。合约管理员能授权其他 Settler 绕过网关策略，仍受合约约束。用量未知时按上限收费，不做事后退款。
2. x402 原生：一条通道同时只处理一个请求（累计凭证的设计），并发靠通道池，每条通道各停一份存款，每钱包最多 128 条。API Key 每 Key 默认 128 并发，共用钱包池。
3. x402 原生：流式调用后下一次会多一轮纠正 402，客户端要能读链。
4. x402 原生的退款按通道各一笔交易：代理 `refund --all` 自动逐条，浏览器钱包每条签一次。API Key 池余额需钱包签名申请取回，等待期满由网关代发；撤销 Key 不等于取回共享池余额。用户直接在链上操作需要自己付 gas。
5. 依赖基金会 facilitator：免费、无 SLA、无公布限速。它不可用时 x402 的存款/claim/退款积压，新鲜镜像可本地核验部分调用，旧镜像与需远端验签的路径会受阻；预付池另走 signer/RPC；它收费时要么付费要么自建（自建后 gas 回到我们付，约每笔 0.02–0.03 MON）。
6. Settler 签名钥匙是 signer 容器里的文件，尚未接入 KMS/HSM；新 API Key 不持授权钥匙；`RESPONSE_ENCRYPTION_KEYS` 仍保护供应商钱包 Key 和旧通道退款钥匙，需安全备份和轮换。
7. 默认使用公共 Monad RPC；生产建议专用 RPC，公共端点没有容量和可用性保障。
8. 本实例正式域名为 router3.ai；独立 Staging 环境未随仓库提供。随附单 PostgreSQL、单 Redis 不是高可用方案。
9. 控制台的登录与签名只在无头浏览器 + 模拟钱包、模拟数据和主网分叉上验证，尚未用真实钱包插件走一遍；手机钱包需要 `WALLETCONNECT_PROJECT_ID`。
10. 不支持音频输入、联网搜索等服务端工具和特殊时段收费模型。
11. 供应商用量是应计依据，最终成本仍需与供应商账单对账。
12. 没有自动重试和跨模型 fallback。
13. 缓存方式取决于上游端点能力，混合或未知能力不盲目注入默认缓存指令。显式写入需要对应报价，一小时 TTL 也需一小时写入价。缓存可用性、最小前缀及保留时间由供应商决定。OpenRouter 按报告成本结算，实际费率依模型与托管商而异。
14. `n`、`best_of` 等扇出参数会被网关丢弃而不是报错。
15. OpenRouter 账户开了 ZDR（`zeroDataRetention: true`）时，托管商只从 OpenRouter 的 ZDR 端点列表里选；`probeHosts: true` 时，每个选中的托管商每周用一次 16 token 的小请求实测（临时 Key，限额 1 美元，用完即删），400/403/404 的托管商剔除（例如只接受自带 Key 的 Azure 端点），429、超时不下结论、下次再测。列表变化或改了账户隐私设置后，要等下一次 catalog 同步（每天）才更新。
16. 智能钱包付款人（`payerAuthorizer` 为零地址）每次都要经 facilitator 用 ERC-1271 验签。
17. 法律、制裁筛查、税务、退款和供应商转售条款不由代码解决。
18. API Key 的冻结与扣费都在钱包预付池账户的行锁下进行；同一钱包的大量并发请求会在这行上排队，延迟随并发增加（单次锁持有为毫秒级）。
19. API Key 的冻结额是估算（输入按字节 ÷ 3，输出最多按 `API_KEY_HOLD_OUTPUT_TOKENS` 即 8192 token 算，`max_tokens` 照原样转发）。实际费用超过冻结额时照扣，但以预付池可付额及 Key 的每日/总剩余额度为界，并为同 Key 的其他进行中请求保留冻结额度。扣不下的差额记为未收，由部署者承担；达到 Key 硬额度不会中断已经派发的模型响应。
20. 预付池补充要一笔链上交易（约 1–2 秒）；可用额不足时请求会等补充，余额刚用完时那一个请求会变慢。补充目标定得太小会让并发受限。
21. Settler 为预付池付 gas（每笔 settle 约 0.025 MON），需要定期给 Settler 充 MON；低于预算时补充和扣款会延后，调用不受影响直到可用额用完。
22. 钱包 SDK 尚有 Zod 3 安全公告未修复；前端审计的 12 个 high 包均由同一公告沿依赖链传播。后端依赖审计为 0，具体范围与升级取舍见 [依赖安全状态](DEPENDENCY_SECURITY.zh.md)。
