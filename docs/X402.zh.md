# x402 支付通道

[English](X402.md)

不带 API Key 的调用都这样付款：客户端（本地代理或 x402 SDK）用钱包私钥给每次调用签凭证。用 API Key 的调用从钱包的预付池扣费，见 [PREPAID_POOL.md](PREPAID_POOL.zh.md)。实现的是 x402 基金会的 `batch-settlement` 方案（[规范](https://github.com/x402-foundation/x402/blob/main/specs/schemes/batch-settlement/scheme_batch_settlement_evm.md)），合约 `x402BatchSettlement` `0x4020074e9dF2ce1deE5A9C1b5c3f541D02a10003`（CREATE2，Monad 主网已部署，非本项目部署），SDK `@x402/core`、`@x402/evm` 2.29.0。

## 两种付款方式

| | API Key（默认） | x402 原生（高级） |
|---|---|---|
| 扣费来源 | 钱包的预付池，所有 Key 共用 | 钱包自己开的通道 |
| 谁签 | 钱包签一次开启自动扣款，之后不用签 | 客户端每次调用签凭证 |
| 客户端 | 任何 OpenAI / Anthropic / Responses 客户端 | 本地代理或 x402 SDK |
| 并发 | 每个 Key 128（`API_KEY_MAX_CONCURRENCY`），受预付池可用额限制 | 通道数（最多 `X402_MAX_CHANNELS_PER_PAYER`） |
| 上链 | Settler 发 `settle`（扣款 + 补充） | facilitator 发 claim / settle |

2026-10-23 到 10-26 之间创建的 Key 各有一条 x402 通道；它们现在也从预付池扣费，通道里剩下的钱可以退回（`POST /v1/keys/:id/refund`，撤销时也会退回）。

## x402 原生：一次调用

1. 客户端不带凭据请求 `/v1/chat/completions`、`/v1/messages` 或 `/v1/responses`。网关校验请求、定价，答 `402`：`PAYMENT-REQUIRED` 头（base64 JSON）给出 `amount`（本次上限，微 USDC）、`payTo`（Treasury）、`extra.receiverAuthorizer`（Settler）、`extra.withdrawDelay`、`extra.minDeposit`。响应体是同格式的错误 `PAYMENT_REQUIRED`，`details.x402.accepts` 是可读副本。
2. 客户端签凭证 `Voucher(channelId, maxClaimableAmount = 已累计 + amount)`，重发请求并带 `PAYMENT-SIGNATURE`。通道余额不够时 SDK 自动把存款授权和凭证打包成 `deposit` 载荷。
3. 网关核验：本地有通道镜像且链上状态在有效期内（5 分钟）就本地验签，否则问 facilitator `/verify`（读链）。通过后在通道上登记一笔待结算（同一通道同时只处理一个请求）。
4. 调用供应商，按实际 token 算费（模型原价 + 服务费），以 `settlement override` 的方式在凭证上记账：累计额只增加实付，不超过上限。非流式响应带 `PAYMENT-RESPONSE` 头；响应体 `gateway.x402` 有 `charged_atomic`、`cumulative_atomic`、`ceiling_atomic`、`transaction`（有存款时）和 `payment_response`。
5. 流式响应无法事后加头：收据放在最后一个数据块的 `gateway.x402.payment_response`。标准 SDK 客户端下一次调用会先收到一次纠正 402（带服务端累计额和它自己签过的凭证），本地核对后重签再成功；这需要客户端能读链（`toClientEvmSigner(account, publicClient)`）。

非流式调用客户端断开后仍会等供应商完成，能取得用量时按实付收费。

失败：供应商在收费前拒绝（`chargeCertainty: not_charged`）→ 取消登记，不收费。用量未知（流被中断、超时、供应商边界后的意外错误）→ **按凭证上限收费**，记 `charged_from = ceiling` 和失败码。这是协议语义（上限是用户签过的），也是供应商会向平台收费的部分。

## x402 原生的并发：通道池

一条通道同时只处理一个请求，因为凭证是累计金额，第 N+1 张要基于第 N 张结算后的累计额签。并发靠多条通道：同一钱包换 `salt` 就是另一条通道，各自存款、各自累计。

- 本地代理 `clients/x402-proxy` 内置通道池：起步一条，全忙再开一条，最多 `X402_MAX_CHANNELS_PER_PAYER`（默认 128，代理侧 `--max-channels`）。通道的 salt 持久化在 `~/.router3/salts.json`，重启沿用。
- 每条通道的存款是 `max(minDeposit, 本次缺口)`；`X402_MIN_DEPOSIT_USDC` 默认 0.1，小通道闲置的钱少。
- 网关按钱包限制通道数：第 129 条存款返回 `402 X402_CHANNEL_LIMIT`。
- claim 时多条通道合进一笔交易，settle 一笔收齐，可分摊交易固定开销，gas 仍随批次规模变化。

## 通道的一生

- 开通：第一次调用自动开通（SDK 的存款策略），或在控制台「通道」页充值（`POST /v1/x402/deposit`，收 0.000001 USDC 让凭证前进一格）。
- 累计：网关只保存最新一张凭证和累计实付（`private.x402_channels`，Postgres 行锁实现 SDK 的 `ChannelStorage`，多副本安全）。
- claim：collector 每 `X402_CLAIM_INTERVAL_SECONDS`（600）扫描，通道未上链金额 ≥ `X402_CLAIM_MIN_USDC`（1）、或闲置超过 `X402_CLAIM_IDLE_SECONDS`（86400）、或链上有取回申请（直接读合约 `pendingWithdrawals`）时，把这些通道的凭证打成一批 `claimWithSignature`，Settler 签 `ClaimBatch`，facilitator 上链并付 gas。随后 `settle(Treasury, USDC)` 把已 claim 的钱转到 Treasury。
- 退款：`GET/POST /v1/x402/refund`，载荷 `type: refund` + 零费用凭证（`maxClaimableAmount` = 累计额）+ 可选 `amount`。网关校验后签 `Refund` 和对应的 `ClaimBatch`，facilitator 在一笔交易里先 claim 欠款再退款。通道记录随后删除；下次调用重新开通。每条通道各一笔：代理 `refund --all` 自动逐条签；控制台「退回全部」每条通道弹一次签名。
- 取回：用户在合约上 `initiateWithdraw(config, amount)`（需要 MON），等待 `withdrawDelay`（默认 86400 秒，合约允许 900–2592000）后 `finalizeWithdraw`。等待期内 collector 看到取回申请即 claim，取回金额被合约限制在未 claim 的余额内。

## 安全边界

- Settler 私钥只在 signer 容器，`signerRef: x402-authorizer-v1` 只签 `ClaimBatch` 和 `Refund` 两种 EIP-712 类型，域固定为合约地址与 chain 143；每条 claim 的 `totalClaimed` 不得超过通道镜像里的累计实付，`maxClaimableAmount` 必须等于镜像里保存的凭证；退款金额不得超过存款减累计实付。API 被攻破也签不出多 claim 或少收的签名。x402 路径由 facilitator 发交易和付 gas；同一个 Settler 仍需 MON 支付预付池交易。
- 付款人白名单复用 `AUTH_ALLOWED_ADDRESSES`：设置后只有名单内的 `channelConfig.payer` 能付款，在任何状态被改动前拒绝。
- 单次上限 `X402_REQUEST_LIMIT_USDC`（默认 5）：上限超过它的请求返回 `402 X402_REQUEST_LIMIT`。
- 速率限制按通道 id 分桶。
- OpenRouter 模型：第一次调用时用管理 Key 给该付款钱包建一把限额调用 Key（有预付池时跟随每日上限，否则使用 `payerKeyLimitUsd`），OpenRouter 侧再兜一层上限。
- facilitator（默认 Monad 基金会的 `https://x402-facilitator.molandak.org`）只做验签、读链和代为上链，拿不到资金；它宕机时新鲜镜像可本地验部分凭证，存款、claim、退款延后；旧镜像与需远端验签的路径会受阻。`X402_FACILITATOR_URL` 可以换成自己跑的实例（`@x402/core` 的 facilitator 代码加一把有 MON 的中继钱包，分叉验收脚本里就是这么跑的）。

## 配置

| 变量 | 说明 |
| --- | --- |
| `TREASURY_ADDRESS`、`SETTLER_ADDRESS`、`SETTLER_SIGNER_URL`、`SETTLER_SIGNER_BEARER_TOKEN` | 收款地址、Settler 地址、signer 服务（API 和 collector 都要） |
| `X402_FACILITATOR_URL`、`X402_FACILITATOR_TIMEOUT_MS` | facilitator 地址与超时（90 秒） |
| `X402_WITHDRAW_DELAY_SECONDS` | 新通道的取回等待期（86400） |
| `X402_MIN_DEPOSIT_USDC`、`X402_REQUEST_LIMIT_USDC`、`X402_MAX_CHANNELS_PER_PAYER` | 402 里建议的最低存款（0.1）、单次上限（5）、每钱包通道数（128） |
| `API_KEY_MAX_CONCURRENCY` | 每个 API Key 同时进行的请求（128） |
| `API_KEY_REQUEST_LIMIT_USDC` | API Key 单个请求的冻结额上限（50）；x402 原生仍用 `X402_REQUEST_LIMIT_USDC` |
| `X402_CLAIM_MIN_USDC`、`X402_CLAIM_IDLE_SECONDS`、`X402_CLAIM_INTERVAL_SECONDS` | collector 的 claim 策略 |
| `STREAM_REQUEST_TIMEOUT_MS` | 不得超过 570000：SDK 的待结算登记最多 10 分钟 |

数据：`private.x402_channels`（通道镜像）、`private.x402_requests`（每次通道付款的账本：上限、实付、累计、用量、`charged_from`）、`private.x402_settlements`（存款、claim、settle、退款的交易日志）。供应商余额对账和 `metrics_x402()` 都基于它们。

## 接口

- `GET /v1/x402`：条款（网络、资产、收款与授权地址、取回等待、最低存款、单次上限、每钱包通道数、合约、facilitator、是否就绪）。
- `GET /v1/models` 不带凭据：可付款的模型列表（OpenAI 格式）。
- `POST /v1/x402/deposit`、`GET|POST /v1/x402/refund`：见上。
- `GET /v1/x402/channels`、`GET /v1/x402/channels/:id/requests`：登录会话查看本人钱包自己签的通道与调用。
- API Key、预付池配置、Key 额度、旧通道退款、撤销与调用记录，见 [HTTP API](API_REFERENCE.zh.md)。

## 客户端

- 本地代理：`node clients/x402-proxy/cli.mjs serve --gateway https://router3.ai`，然后 `OPENAI_BASE_URL=http://127.0.0.1:8402/v1`；`refund --all`、`status`。私钥来自 `ROUTER3_PAYER_KEY` 或 `ROUTER3_PAYER_KEY_FILE`。
- 直接用 SDK：`@x402/fetch` + `@x402/evm/batch-settlement/client`，一个 scheme 实例一条通道；给 agent 可以用单独的会话密钥签凭证（`payerAuthorizer`）。

## 已知限制

- x402 原生：一条通道同时只处理一个请求；并发靠通道池，每条通道各停一份存款。API Key 没有这个限制。
- 新 API Key 不创建代签凭证钥匙，其信任与额度边界见[预付池](PREPAID_POOL.zh.md#平台能动用多少)。
- 流式响应需要一次纠正 402，并要求客户端有链上读能力。
- 用量未知时收上限，不做事后对账退款。
- 智能钱包（`payerAuthorizer` 为零地址）每次都要经 facilitator 用 ERC-1271 验签，没有本地快速路径。
- 退款按通道各一笔：浏览器钱包每条签一次。
